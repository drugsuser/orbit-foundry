# Orbit Foundry — техническое руководство

**Сайт:** https://drugsuser.github.io/orbit-foundry/  
**Репозиторий:** https://github.com/drugsuser/orbit-foundry  
**Публикация:** GitHub Pages, ветка `main`, корень `/`, файл `.nojekyll`.

Интерактивная настольная гравитационная песочница на обычном JavaScript и Three.js.
Интерфейс — на русском. Единственный стартовый сценарий — Солнце и восемь планет;
инструменты создания тел, манёвров, чёрных дыр и столкновений остаются доступны.
Это **наглядная приближённая модель, не астрономическая эфемерида и не гидрокод**.

Этот README — точка входа для разработчика или агента без истории переписки.
Описана текущая реализация: энергетически ограниченные контакты `energy1`, геометрия на базе `solid6`,
управление камерой `controls1` на базе `nav7`.
Эти названия — метки итераций и HTTP-кэша, **не версия формата сохранения**:
сохранения по-прежнему имеют `format: "orbit-foundry", version: 1`.
При расхождении описания с последующими изменениями источником истины служит код.

## 1. Быстрый старт и правила продолжения работы

Из корня проекта:

```sh
python3 -m http.server 8000
```

Открыть http://localhost:8000/ в современном настольном браузере.
Нужны WebGL, ES modules и Web Worker. Сборка, серверное API, база данных, ключи,
авторизация и внешний runtime-CDN не нужны. Не открывать `index.html` через
`file://`: модули, загрузка текстур и Worker должны обслуживаться по HTTP(S).

- При ширине окна **≤ 1000 CSS px** показана намеренная заглушка «Этому космосу
  нужен простор». Рабочий интерфейс проверять на ширине **больше 1000 px**.
  Мобильная версия намеренно не реализована. Текст заглушки говорит «от 1000»,
  но фактическая граница в CSS/обработчиках включает 1000.
- Первый запуск приостановлен. После загрузки материалов камера показывает Землю.
  `Space` запускает/останавливает орбитальную динамику.
- В старой рабочей среде исходники находились в `/data/orbit-foundry-web`, сервер
  работал на `8037`. Это **не требование проекта**: пути и порт можно менять.
- Читать и править актуальные `engine.js`, `scene.js` и связанные файлы напрямую.
  Не восстанавливать приложение из старых генераторов или скриншотов.
- Сначала воспроизвести проблему, сохранить рабочую копию/коммит, затем делать
  минимальную правку и проверять поведение. Не смешивать изменение UI с заменой
  физической модели без явной необходимости.
- Изображение поверхности может отставать от физики: это сознательная асинхронная
  схема. **Не останавливать интегратор в ожидании Worker.**
- Не обещать научную достоверность, сохранение механической энергии при разрушении
  или гарантированный FPS на любом GPU.

| `assets/` | Локальные карты планет, Земли, облаков, ночных огней и колец. Часть исходных Earth/Moon-карт упакована в JS-модули с data URL; такие импорты тоже используются. |
| `vendor/` | Локальный Three.js **0.180.0** и лицензия. Runtime импортирует `three.module.min.js`; его локальные зависимости также должны быть доступны. |
| `ASSET_CREDITS.md` | Авторы, конкретные источники карт, лицензии и ссылки на справочные данные. Сохранять при распространении. |
| `.nojekyll` | Отключает обработку Jekyll на GitHub Pages. |

**Исторические вспомогательные файлы.** В старой рабочей копии также есть
`build.py`, `finish.py`, `preview.cjs`, `tests/regression.cjs`, `tests/edge-tests.cjs`,
логи, результаты и изображения. Они не являются runtime-зависимостями или
обязательным шагом сборки. `build.py` восстанавливает файлы из старой монолитной
версии с жёсткими `/data/...` путями; `finish.py` применяет старые текстовые замены.
**Не запускать их поверх текущей версии:** они могут перезаписать актуальные
исходники. Наличие этих файлов в конкретном checkout нужно проверять отдельно.

Порядок подключения в конце `index.html`:

```text
impact-physics.js → solid-physics.js → engine.js → scene.js (type="module")
                                             ↑
                        scene.js читает уже созданный OrbitFoundry
```

URL `engine.js` в HTML имеет `?v=controls1`; остальные скрипты/CSS, Worker
в `scene.js` и его `importScripts` — `?v=energy1`. При изменении общего модуля
физики обновлять оба уровня Worker.
Список версий нужно сверять в самих файлах.

## 3. Архитектура и жизненный цикл

Два слоя изображения: `#webgl` с canvas Three.js под прозрачным `canvas#space`.
Верхний Canvas рисует подписи, выделение, траектории, стрелки, компас и часть
эффектов; DOM-панели лежат выше. Перехват мыши идёт через `#space`.

1. `engine.js` создаёт API, загружает `solar`, рассчитывает ускорения и запускает
   единственный основной `requestAnimationFrame(frame)`. Первый старт ставится на паузу.
2. `scene.js` создаёт WebGLRenderer, камеру, свет, Worker и TextureLoader.
3. После загрузки материалов `LoadingManager.onLoad` убирает загрузочный экран
   и вызывает `api.focusShowcase(true)`.
4. На каждом кадре `engine.frame`:
   - считает wall-clock дельту: не более `0.2 s`; физическая дельта — не более `0.05 s`;
   - если мир не на паузе, вызывает `simulate(dt * rate)`;
   - обновляет следы, перелёт/сглаживание зума и слежение за телом;
   - применяет клавиатурную навигацию по wall-clock времени, независимо от паузы;
   - вызывает `draw`, а тот — `FoundryRenderer.render` и Canvas-оверлей;
   - примерно раз в `200 ms` обновляет статистику и основной UI;
   - при отсутствии pointer-жеста периодически пересчитывает прогноз орбиты.
5. Рендер выгружает готовые части сетки с ограничением времени, синхронизирует
   объекты с телами, обновляет материалы/свет/вращение, отправляет следующую
   задачу Worker и рисует сцену.

`bodies` — источник физического состояния. Three.js-объект не является источником
массы, положения или формы контакта. `selected` и `follow` — разные ID:
выбранное в инспекторе тело не обязательно находится по центру камеры.

## 4. Единицы и системы координат

### Физический движок (`engine.js`)

| Величина | Внутренняя единица / константа |
| --- | --- |
| `x,y,z`, `r`, softening | астрономические единицы, AU |
| `mass` | массы Солнца, M☉ |
| `t`, шаг интегратора | юлианские годы по `31557600 s` |
| `vx,vy,vz` | AU / год |
| `ax,ay,az` | AU / год² |
| `G` | `4 * Math.PI ** 2` в этих единицах |
| `AU` | `149597870.7 km` |
| `MS` | `1.98847e30 kg` |
| `YR` | `31557600 s` |
| `VUNIT` | `AU / YR` в km/s; UI-скорость делится/умножается на этот коэффициент |
| `C` | `299792.458 / VUNIT` в AU/год |
| `rate` | годы симуляции / секунду wall-clock; ползунок задаёт `log10(rate)` |

`impact-physics.js` и SI-часть `solid-physics.js` используют
`AU = 149597870700 m`, `G = 6.67430e-11` и скорости в m/s.
Поэтому **одинаковое имя `AU` в разных файлах не означает одинаковую единицу**.
SI-G и `4π²` — отдельно заданные приближения; не ожидать побитового совпадения
между двумя системами констант.

### Координаты формы и изображения

- Мировая плоскость орбит — **XY**, вертикальная ось — **Z**.
- Локальное тело имеет исходный радиус **1**. Координаты выреза и его `r` заданы
  в долях исходного радиуса тела, не в AU, километрах или пикселях.
- `solidQuaternion = [x,y,z,w]` связывает локальную форму с мировой системой.
  Преобразования выполняют `SolidPhysics.local/world/rotate`.
- В WebGL `SCALE = 10000` scene units / AU. Положения объектов вычисляются как
  `(body.position - cam) * SCALE`: это origin rebasing около центра кадра,
  а не абсолютные AU в GPU.
- Визуальный радиус имеет минимальный пиксельный размер и множитель `sizeScale`.
  **Физические контакты используют `b.r`, а не увеличенную видимую сферу.**
- `scale` камеры — масштаб проекции в px/AU в плоскости центра кадра; это не
  параметр масштаба физических тел и не `SCALE` рендера.

## 5. Данные тела и начальная система

`engine.body(o)` создаёт тело и назначает положительный уникальный `id`.
Основные поля:

```js
{
  id, name, kind, planet, mass, r,
  x, y, z, vx, vy, vz, ax, ay, az,
  color, ring, trail, tidalDone,
  previous,                 // положение до последнего drift для swept-контакта
  phase, hot, spread, born,  // в т.ч. представление облаков выброса
  solid, solidQuaternion, solidSpin, solidLock,
  scars                     // небольшая история визуальных следов удара
}
```

- `kind`: `star`, `rock`, `gas`, `bh`, `asteroid`, `debris`.
- `planet`: ключ карты из `sun, mercury, venus, earth, mars, jupiter, saturn,
  uranus, neptune` либо `null`; не определяет физику самостоятельно.
- `phase: "dust"` — агрегированное облако с массой и скоростью центра, не набор
  независимых N-body частиц. Точки облака — визуализация. Его масса всё ещё
  участвует в `accel`/статистике, но облако пропускается в контактах и парных
  ограничениях `safeStep`.
- У `bh` радиус переопределяется как `2GM/C²` при создании и импорте.
- `solidLock` останавливает декоративное вращение повреждённого ядра.
  `solidSpin` и quaternion сохраняют ориентацию геометрии после импорта.
- `trail`, ускорения, `previous` и большинство рендер-кэшей — временные данные.
- `dustKey` объединяет порции выброса в текущей сессии; в JSON он не экспортируется.

`solar.build` создаёт **9 тел**, без Луны: приблизительные массы, радиусы и
орбитальные расстояния планет; начальные фазы заданы `i * 2.31 + 0.8`.
Начальные скорости близки к круговым двухтельным, у Меркурия есть небольшой
наклон. Затем `centerMomentum` переводит систему в барицентрическую систему.
Это не состояние Солнечной системы на конкретную дату. В стандартной системе
Земля получает ID `4`; в пользовательских сохранениях на этот ID полагаться нельзя.

`loadScene` принимает **только `"solar"`**. Старые `"empty"`, `"collision"`,
`"blackhole"` удалены из сценариев и выбрасывают исключение. Для тестовой системы
нужно собрать валидный `payload` и вызвать `restore`, а не возвращать скрытые сцены.

## 6. Гравитация, время и диагностика

### Интегрирование

Ключевые функции: `accel`, `safeStep`, `leap`, `simulate`, `contacts`.

- `accel` обходит пары симметрично, **O(n²)**. Ускорения используют сглаживание
  `soft²` и дополнительный нижний предел знаменателя
  `0.25 * (a.r + b.r)²` для сильно сблизившихся центров.
- `leap(dt, arr)` — kick–drift–kick / leapfrog: половина импульса, перенос
  координат, пересчёт ускорений, вторая половина импульса.
- Перед переносом сохраняется `b.previous`.
- `safeStep` выбирает минимум из динамического времени пары и времени пересечения;
  для близких сопоставимых тел дополнительно ограничивает шаг по меньшему радиусу.
- `simulate(wanted)` использует `min(rem, safeStep(), 0.02)` лет на подшаг.
  Лимиты: **180 подшагов за вызов** и проверка CPU-бюджета **15 ms каждые 6 шагов**.
  Это мягкие лимиты: один дорогой шаг может занять больше.
- Невыполненный остаток запрошенного времени не переносится автоматически в долг.
  Симуляция замедляется; UI сообщает `CPU: время замедлено`.
- Недопустимый шаг останавливает мир. Не лечить `NaN` бесконтрольным увеличением
  минимального шага: можно потерять быстрые контакты.

Значения точности: `0.015`, `0.035`, `0.07`; меньше — дороже и обычно точнее.
Начальный `soft = 1e-6 AU`, допустимый диапазон настройки/импорта — `1e-10…1 AU`.
По умолчанию `collision: "fragment"`, `accuracy: 0.035`, `tides: true`, `rel: false`.

### Чёрные дыры и условная «ОТО»

`rel` добавляет к паре с чёрной дырой приближённый множитель
`1 + 3h²/(r²C²)` в силе. Это не полноценная постньютоновская схема и не GR solver.
Горизонт задаётся радиусом Шварцшильда; захват и приливной разрыв — отдельные
упрощённые правила. Визуальная воронка/линзирование не меняют физические силы.

### Статистика

`updateStats` считает суммарную массу, модуль полного линейного импульса, центр
масс, кинетическую и сглаженную потенциальную энергию. `baselineDirty` сбрасывает
эталон `energy0` после внешних правок/контактов, поэтому **ΔE около нуля после
столкновения не доказывает сохранение энергии**. Энергетический диагностический
потенциал не включает в точности радиусный clamp силы и опциональную `rel`-поправку;
это не универсальный строгий инвариант всех режимов.

Орбитальные элементы (`elements`) — мгновенная двухтельная оценка относительно
`dominant(b)`, не решение всей N-body системы. Температура — условная равновесная
оценка с альбедо `0.3`, фоном `2.725 K` и приближённой зависимостью светимости от
массы; не климат, не температура удара и не газодинамика.

## 7. Создание тел, орбиты и манёвры

- Инструменты `select/orbit/launch/delete` выбираются кнопками или `1/2/3/4`.
- **На орбиту:** `orbitAnchor` закрепляет выбранное центральное тело. Новое тело
  и центр получают взаимную поправку скоростей из относительной круговой скорости
  `sqrt(G * (M + m) / r)`. Создание следующего тела не должно незаметно менять центр.
- Радиус нового обычного тела масштабируется как `preset.r * cbrt(mass/preset.mass)`:
  это постоянная плотность пресета. Чёрная дыра использует свой закон радиуса.
- **Запуск мышью:** `launchVelocity` задаёт направление в плоскости XY через
  `unproject(..., world.z)`. Скорость = длина стрелки / 100 px × `launchGain` km/s.
  Мировой режим не добавляет скорость выбранного тела; относительный режим
  (`launchFrame === "relative"`) добавляет её явно через `initialLaunchVelocity`.
- Во время прицеливания LMB симуляция приостановлена, слежение отключено,
  клавиатурный полёт заблокирован. `cancelPointer` восстанавливает предыдущее
  состояние паузы и очищает прогноз; `blur` также отменяет жест.
- `previewLaunch` считает ограниченный прогноз на копиях тел: до 1600 шагов,
  с мягким бюджетом 12 ms, до 100 тел. Это не гарантированная полная траектория;
  прогноз заканчивается у контакта и не моделирует последующее разрушение.
- `spawn` отклоняет создание внутри исходной физической сферы существующего тела,
  даже если в его видимой геометрии есть вырез. Для чёрных дыр и орбит см. исходники
  `candidate`, `spawn`, `orbitVel`.
- `burn(+1/-1)` добавляет Δv вдоль/против скорости относительно доминирующего тела.
  Это внешнее воздействие, не расход топлива и не модель двигателя.

Отдельная лаборатория удара (`launchImpact`) отличается от ручного запуска:
масса вводится в **kg**, радиус в **km**, относительная скорость в **km/s**.
Ударник стартует сбоку на расстоянии `3.6 * (R₁ + R₂)`, со скоростью цели плюс
заданной относительной скоростью. Параметр `b` — смещение в долях `R₁ + R₂`:
`0` — лобовой, около `0.72` — скользящий, `>1` — номинальный пролёт.
Гравитация может изменить фактическое сближение.

`launchImpact` принудительно включает `fragment`, подбирает скорость времени и
запускает мир. При автопаузе остановка наступает **после расхождения/итога**,
а не на первом касании. Для пропустившего цель ударника итогового события может
не быть — автопауза не является таймером пролёта.

## 8. Столкновения и удаление материала

### Маршрутизация контактов

1. `SolidPhysics.candidates` — sweep-and-prune по swept AABB между `previous` и
   текущей позицией. Dust исключается. Для включённых приливов отдельно добавляются
   консервативные пары со всеми чёрными дырами, т.к. радиус Роша больше горизонта.
2. Обычные сферы проходят `ImpactPhysics.swept`: пересечение относительного
   отрезка движения со сферой суммарного радиуса.
3. Чёрные дыры используют отдельный тест захвата по текущему расстоянию, не тот
   же полный swept-тест. Не считать все виды захвата continuous collision detection.
4. Звёзды/чёрные дыры и режим `merge` идут в `merge`. Звёзды и ЧД сохраняют
   поглощение даже при `collision: "none"`.
5. `bounce` даёт нормальный упругий импульс и раздвигает сферы с весами по массе.
6. `fragment` направляет обычные тела в **`materialContact`**, а не в набор
   случайных крупных сферических обломков.

`ImpactPhysics.analyze` использует приведённую массу и SI-энергию
`0.5 * μ * v²`, угол/интенсивность удара, прочность и гравитационный масштаб.
Поля `severity`, `largestFraction`, `critical` — приближённые прокси, не
калиброванная модель разрушения. `ImpactPhysics.fragments` остаётся в модуле
как вспомогательный/исторический метод; текущий обычный `fragment`-resolver его
**не вызывает**. Исключение с дискретными обломками — отдельный `splitBody` для
приливного разрыва у ЧД, который создаёт 7 тел с уравновешенными приращениями скорости.

### Представление формы

```js
solid: {
  mass0,          // масса при первом создании solid-состояния
  cuts: [{ x, y, z, r, /* optional: crater, angle, depth */ }],
  extraLoss,      // аналитическая поправка массы для подрешёточных кратеров
  revision
}
```

Поле в локальных координатах:

```text
field(p) = max(length(p) - 1, cut.r - length(p - cut.center) для всех cuts)
field < 0 → вещество; field = 0 → поверхность; field > 0 → пустота
```

Это sphere-minus-union-of-spheres / CSG-поле, используемое **и** контактом,
**и** реконструкцией сетки. Это не набор decal-пятен и не точное signed-distance
поле произвольной деформируемой породы.

- `state` создаёт `solid`; `cut` добавляет вырез, удаляет избыточные вложенные
  вырезы и обновляет массу/revision. Лимит — **256 cuts на тело**.
- Масса остатка оценивается центрами ячеек решётки **36³** внутри исходной сферы.
  Кэш проб хранится в `WeakMap`, а не экспортируется в JSON.
- `overlap` проверяет оставшееся вещество набором проб в области пересечения,
  а не делает точное непрерывное пересечение треугольных сеток.
- Контактная форма и видимая сетка имеют разное разрешение. Узкие/подрешёточные
  детали и быстрые вырезы не обязаны совпадать с точностью до одного треугольника.

### Малый ударник / кратер

При `min(radius)/max(radius) < 0.055` и отсутствии уже начатой пары используется
`excavate` → `SolidPhysics.crater`. Цель/ударник в `analyze` выбираются по массе;
обычный ожидаемый случай — маленький и менее массивный ударник.

Размер кратера оценивается по радиусу ударника, скорости, плотностям и g; затем
создаётся сферический вырез с настоящим дном и стенками. Если решётка 36³ не
разрешает объём, учитывается аналитическая поправка `extraLoss`. Геометрический
кандидат дополнительно уменьшается до оплачиваемого энергетическим бюджетом
объёма; отчёт/inspection используют фактические угол и глубину. Если кратер
неразрешим, ударник не исчезает: применяется ограниченный контакт.
Ударник расходуется, его масса и вырезанная масса цели переходят в выброс.
Скорости остатка/выброса рассчитываются с учётом линейного импульса.

Километровый астероид оставляет кратер километрового масштаба, а не дыру на
полпланеты. Невидимый с глобального расстояния малый кратер — нормальное
поведение. Кнопка **«Рассмотреть вмятину»** вызывает `inspectImpact`: пауза,
косой близкий ракурс, нейтральный материал без текстуры/облаков и отдельный свет.
«К планете» возвращает общий вид. Снимок камеры из этого режима нормализуется
в `payload`, а не экспортирует экстремальный inspection-зум буквально.

### Сопоставимые тела / срезание

- `contactPairs` хранит пару, начальные массы, скорость, последний срез и итог.
- Ядра сохраняют ID, исходный радиус и ориентацию. `solidLock = true` не позволяет
  декоративной осевой анимации унести кратер из контактных координат.
- `shave` предлагает локальную сферу второго тела, но `limitedCut` уменьшает
  её радиус при недостатке энергии. Старый бинарный порог `8e6 Pa` удалён.
  Если допустимая масса меньше ячейки 36³, срез не создаётся бесплатно.
- Повторная обработка отсекается, пока относительное смещение меньше
  `0.035 * minRadius` после предыдущего среза.
- Скорости остатков и выброса рассчитываются общим энергетическим resolver.
  Полностью израсходованное ядро удаляется; маленький остаток больше не
  переводится в выброс бесплатно по порогу `0.003 * mass0`.
- `finishContacts` завершает пару после удаления участника или расстояния
  не меньше `1.025 * (R₁ + R₂)` (после ограниченной нормальной реакции —
  `R₁ + R₂`). Тогда обновляется отчёт и срабатывает автопауза.
- `depositDust` объединяет выброс по ключу в агрегированное облако с массой и
  центром движения. Не путать его 1800 визуальных точек с 1800 физическими телами.
  Перед срезанием резервируются места для облаков. При исчерпании лимита
  срез не выполняется: применяется неупругая реакция без потери массы.
  Legacy fallback в `depositDust` остаётся защитой для сторонних вызовов,
  но обычный resolver до него не доходит.

### Общий бюджет контакта (`energy1`)

`ImpactPhysics.contactBudget` создаётся **один раз на пару**, не на каждый шаг.
Начальный бюджет ограничен `analyze.deposited` и относительной COM-энергией
`E = 0.5 * μ * v²` в SI. Повторные cuts расходуют остаток, не пополняя его.

- Удельная стоимость удаления: `q = strength / density + 0.15 * G * M / R`
  (J/kg, минимум 1). Плотность материала использует `solid.mass0`; гравитационная
  часть на старте пары использует текущую массу. Коэффициент 0.15 — явно
  эвристическая доля подъёма вещества, **не закон кратерообразования и не
  требование полного ухода выброса на бесконечность**. Прочность: rock 5 MPa,
  asteroid 0.5 MPa, debris 0.2 MPa, gas 0.
- На одном шаге доступно не больше остатка бюджета и текущей относительной
  энергии. До 75% доступного — на удаление; для двух ядер половина этой доли
  выделяется каждому. Неиспользованная доля не тратится.
- `limitedCut` ограничивает **геометрию**, а не только `b.mass`: сначала точная
  формула пересечения исходных сфер и 22 скалярных итерации, при необходимости
  ограничение живых проб через линейный order statistic. Сетка Worker не
  строится пробно. Оценка объёма консервативна для уже повреждённых тел.
- Стоимость `removedMass * q` списывается из относительной кинетической энергии.
  Для срезания на выброс выделяется не больше `work / 3`, остатка бюджета и
  остатка текущей кинетической энергии. Половина — скорость центра облака с
  отдачей ядра, половина — неразрешённая внутренняя дисперсия (`spread`).
  При объединении облаков `spread²` усредняется по массе, а не берётся максимум:
  добавление холодной массы не создаёт бесплатную энергию расширения.
- Общая скорость центра масс сохраняется; охлаждается относительное движение
  источников, затем добавляются попарно уравновешенные скорости ядра/его выброса.
  Поэтому сумма кинетической энергии агрегатов плюс оплаченные разрушение и
  внутренняя дисперсия не превышает входную COM-энергию этого шага.
- Для малого кратера ударник включается в одно облако; его поглощение неупругое.
  Отдача и разлёт ограничены остатком того же бюджета, неоплаченная энергия
  разлёта не создаётся. Неиспользованная входная энергия трактуется как нагрев.
- Если ограниченный вырез оставил контакт вещества, применяется нормальный
  импульс с `restitution = 0.12` и массово-взвешенная коррекция проникновения.
  Это не глобальный отскок каждого скоростного срезания. Потеря кинетической
  энергии импульса записывается как `contactHeat` и уменьшает остаток бюджета.
- `lastImpact.budget` содержит `initial/remaining/fracture/ejecta/internal/
  contactHeat/qA/qB`; все энергии — J. `internal` — часть `ejecta`, не ещё одно
  дополнительное списание. Бюджет транзитный: import по-прежнему сбрасывает пары.

Это энергетически ограниченный proxy, не SPH/FEM. В частности, позиционная
коррекция контакта может менять гравитационную потенциальную энергию; угловой
момент, тепловое состояние и движение внутри облака не решаются. Не объявлять
локальное неувеличение кинетической энергии сохранением полной энергии мира.
Низкоскоростное слияние обычных тел не добавлено: без модели диссипации/формы
связанного остатка условие `v < escape` само по себе не доказывает слияние.

## 9. Worker и конвейер геометрии

### Выбор реконструкции (`solid-mesh-worker.js`)

- **Radial:** кратеры и формы, которые текущая эвристика считает радиальными.
  Базовый икосаэдр после 5 разбиений, адаптивное согласованное уточнение по
  вырезам, 20 кэшируемых участков. Целевая детализация края: угол / 8 в
  `preview`, угол / 28 в `final`, с внутренними ограничениями глубины/шага.
- **Grid:** если не-кратерный вырез удовлетворяет
  `length(cut.center) < cut.r + 0.002`, включается нерадиальный путь.
  Марширующие тетраэдры на **52³ ячейках / 53³ узлах**, область примерно
  `[-1.03, 1.03]³`, **64 чанка по 13³ ячеек**.
- Эвристика выбора — не математическое доказательство star-shaped формы.
  Нельзя гарантировать корректность всех произвольных сочетаний cuts.
- Radial повторно использует топологию/вершины; grid обновляет поле и чанки
  в затронутой области. Границы чанков читают общие значения решётки.
- Новое состояние, смена метода или немонотонная замена формы требуют reset.
  Переход radial preview → final заново уточняет нужные области.
- Кэш Worker ключуется `id:epoch`; есть ограничение числа сохранённых состояний
  (очистка старого при размере Map больше 24). Это не долговременное хранилище.

### Контракт сообщений

```js
// Главное окно → Worker; solid отправляется structured clone.
{ id, epoch, token, solid, quality: "preview" | "final" }

// Worker → главное окно.
{
  id, epoch, token, quality, reset, method,
  patches: [{ key, position, normal, uv, interior, triangles, volume }],
  triangles, volume, totalPatches, updatedPatches, evaluated, milliseconds
}
// При ошибке: { id, epoch, token, error }
```

`position/normal/uv/interior` — typed arrays; их ArrayBuffer передаются как
**transferable**, а не копируются повторно. `interior` отличает внутренний материал
от внешней текстурированной оболочки в шейдере. `volume`/`meshAudit` — диагностика
сетки, **не источник физической массы**.

### Планировщик (`scene.js`)

- `meshBusy`: **одна глобальная выполняющаяся задача**, не одна на каждое тело.
- `meshLatest`: только последнее ожидающее состояние каждого тела; промежуточные
  revisions схлопываются. Отправка задач — не чаще одного старта за 40 ms.
- `meshUploads`: готовые ответы, ожидающие загрузки в GPU. Новая задача не стартует,
  пока есть незавершённая загрузка ответа.
- Во время активной пары `meshQuality` выбирает preview; после расхождения — final,
  даже если номер revision не изменился. Не убирать quality из проверки актуальности.
- `token` сопоставляет ответ с выполняющимся запросом. `epoch` разделяет кэши
  объектов с повторно использованными ID. Ссылки на объект рендера и `b.solid`
  проверяются перед постановкой/загрузкой ответа: старое сохранение или reset
  не должны применить запоздалую сетку к новому телу с тем же ID.
- Физика продолжает использовать свежий `SolidPhysics.field`; отображается
  последняя готовая сетка, пока более новая строится. Допустимое отставание
  изображения не означает пропуск физического контакта.
- `drainMeshUploads` имеет **мягкий бюджет 3 ms на кадр**. Один driver/shader call
  может превысить его. Буферы переиспользуются при достаточной ёмкости.
- Полностью новая сетка/reset собирается в отдельном target и подменяется после
  подготовки всех частей. Инкрементальные изменения существующих частей могут
  поступать по кадрам. Не показывать половину первичной поверхности.
- Ошибка Worker логируется. `onerror` очищает очереди; резервной синхронной
  реконструкции и гарантированного автоматического восстановления Worker нет.

Диагностика: `FoundryRenderer.meshStats`, `FoundryRenderer.pendingSolids()`,
`FoundryRendererInfo.objects.get(id).meshAudit`. Суммы `workerMs/uploadMs` —
накопленные времена, не длительность одного кадра. `pendingSolids() === 0`
означает отсутствие работы в очередях на этот момент; запрос может появиться
на следующем render после новой revision.

## 10. Рендер, материалы и вращение

- WebGLRenderer: antialias, `ACESFilmicToneMapping`, sRGB output, exposure `1.05`,
  pixel ratio не выше `1.7`; Canvas-оверлей ограничивает DPR отдельно до `2`.
- Общая неповреждённая сфера — `SphereGeometry(1, 96, 64)`, ориентированная под Z-up.
  Планеты не должны заменяться одной перекрашенной картой Луны.
- Для Земли: дневная карта, normal/specular, карта ночных городов, отдельные облака
  и декоративная атмосфера. У других планет — свои локальные карты.
- Юпитер/Сатурн визуально сплюснуты. У Сатурна прозрачные кольца с радиальным UV
  и приближённой аналитической тенью; у Урана — иллюстративные слабые кольца.
- Источник света располагается у наиболее массивной звезды. Терминатор следует
  направлению на Солнце, а не повороту текстуры или камеры. Заполняющий свет
  отдельно управляется режимом освещения/inspection.
- Освещённость нормализована для просмотра: это не физический inverse-square
  exposure, не фотометрия колец и не атмосферный radiative transfer.
- Поле потенциала/воронка и линзирование звёзд — визуальные эффекты.
  `curvature`, `fieldMode`, `fieldStrength`, `lensing` не заменяют `accel`.
- Повреждённая геометрия использует тот же UV/внутренний материал; шейдер
  `decorateSolidMaterial` добавляет вид внутренней поверхности и затухающий жар.
- Удалённые/изменившие тип тела освобождают геометрию/материалы через `disposeObject`.
  Не создавать новые BufferGeometry/материалы без соответствующего disposal.

**Два независимых времени вращения:**

1. Demonstration spin (`rotationMode` по умолчанию): Земля делает оборот за
   40 wall-clock секунд, остальные планеты имеют свои наглядные периоды.
   Пауза орбит не останавливает такое вращение.
2. Simulation-time / `physical`: вращение связано с прошедшим временем мира
   и сидерическими периодами. Пауза останавливает оба движения.

`spinToggle` независимо останавливает осевое вращение. `prefers-reduced-motion`
отключает автоматический demonstration spin и анимированный перелёт камеры.
Венера и Уран имеют ретроградность через наклон оси >90°: не добавлять второй
минус к углу вращения, иначе получится двойной разворот. Фазы, долготы осей и
видимые ускоренные периоды не привязаны к конкретной календарной дате.

## 11. Камера и управление

### Главное: `cam` — НЕ позиция глаза

`cam = {x,y,z}` — **центр кадра / look-at** в мировых AU. Three.js-камера находится
на смещении относительно этого центра. FOV — **42°**.

```text
distance = H / (2 * tan(21°) * scale)             // AU
n = (sin(yaw)*sin(tilt), cos(yaw)*sin(tilt), cos(tilt))
eyeWorld = cam + n * distance
forward = -n
```

`cameraBasis` вычисляет eye/forward/right/up; `scene.sync` строит соответствующую
Three.js-камеру с origin rebasing. `tilt = 0` — сверху по −Z;
`tilt = π/2` — взгляд у плоскости XY. Даже вид сверху остаётся **перспективной**
камерой, не OrthographicCamera. В полюсе используется специальный up-vector.

- В слежении `follow` каждый кадр переносит look-at в центр тела; ПКМ/стрелки
  вращают камеру вокруг тела.
- В свободном режиме `rotateCamera` сохраняет eyeWorld и меняет направление
  взгляда на месте. После вращения пересчитывается look-at.
- При выходе из точного вида сверху есть поправка yaw, чтобы не перевернуть экран.
- W/S перемещают и look-at, и глаз вдоль взгляда, A/D — вдоль экранного right,
  Q/E — вдоль экранного up (это **не обязательно мировая ось Z**).
- Полёт отключает follow/перелёт и inspection, но не снимает выбор в инспекторе.
- Диагональ нормализована. Базовая скорость = минимум `0.65 * distance` и
  `0.8 * clearance` с нижним порогом; Shift умножает её на 4.
- Clearance берётся до исходных сфер с визуальным `sizeScale`. Swept-проверка
  перемещения глаза с оболочкой `1.015 * radius` препятствует туннелированию
  **клавиатурного полёта** через целое тело. Это не универсальная защита всех
  методов перемещения/зума. Изнутри исходной сферы проверка не применяется;
  повреждённые тела приближены ограничивающей сферой, не формой кратера.
- ЛКМ/СКМ-перетаскивание панорамирует в плоскости экрана, а не пересекает луч с XY:
  так панорамирование не становится сингулярным у горизонта. Размещение/запуск
  тела по-прежнему используют свой `unproject` на заданную плоскость Z.
- Зум сглаживается экспоненциально. В слежении `maxZoom` ограничивает приближение
  снаружи сферы, в свободном режиме этот предел по выбранной планете не действует.
- `focusPlanet` учитывает панели, размер тела и кольца; обычный перелёт ≈1000 ms,
  immediate/reduced-motion обходят анимацию.

| Выбор / орбита / запуск / удаление | 1 / 2 / 3 / 4 |

Новые команды полёта/возврата/сверху используют `KeyboardEvent.code`, поэтому
работают на физических WASD и в русской раскладке. **Не все старые буквенные
шорткаты переведены на code**: F/C/G/H/P по-прежнему проверяют `e.key`.
Горячие клавиши не должны перехватывать ввод в input/select/textarea/contenteditable
или Ctrl/Meta/Alt-комбинации. `keyup`, `blur`, `visibilitychange`, вход в поле,
сцена/reset и справка очищают held keys. Во время ПКМ-жеста разрешены WASD/Q/E,
Shift и стрелки: можно одновременно лететь и поворачивать взгляд. ЛКМ/СКМ-панорама
и прицеливание запуска по-прежнему блокируют клавиатурную навигацию.

Вкладка **«Вид» → «Чувствительность ПКМ»**: множитель 0.2–3 (20–300%),
по умолчанию 1, шаг 0.05. Он применяется только к углам мышиного поворота,
не к скорости полёта, стрелкам, панораме или зуму. «Сбросить чувствительность»
возвращает 100%. Настройка сохраняется в `localStorage["orbit-foundry-look-sensitivity-v1"]`
текущего origin; недоступное хранилище не ломает управление. Это предпочтение
пользователя, не поле JSON-сохранения мира; reset/import его не сбрасывают.

HUD показывает следование/свободный полёт, попадание центрального луча, направление
в мировых осях и выбранное тело вне кадра. Определение «в центре» использует
**сферическую оболочку**, не raycast точной повреждённой сетки; это ориентир.
Крестик виден в свободном режиме. Планетная подпись скрывается, когда слежения
за выбранной планетой нет. `project(...).behind` не позволяет выбирать тела за глазом.

## 12. Сохранения и импорт

`payload()` возвращает JSON-совместимое состояние:

```text
format, version, scenario, t, nextId, selected, follow, paused, rate,
settings { collision, accuracy, soft, tides, rel },
ui { launchFrame, launchGain, curvature, fieldMode, fieldStrength, lensing },
camera { x, y, z, scale, yaw, tilt },
bodies [ физические поля + planet/ring/tidalDone/phase/hot/scars/solid/
         solidQuaternion/solidSpin/solidLock/spread/born ]
```

- «Сохранить» пишет **один слот** `localStorage["orbit-foundry-v1"]` текущего origin.
  Сохранение с localhost не разделяется с GitHub Pages и другим портом/origin.
- Экспорт скачивает JSON, импорт читает файл не более **2,000,000 bytes**.
  Квота localStorage отдельная; большой экспорт не гарантирует успешный local save.
- `restore` сначала валидирует данные, затем заменяет мир. Требует version 1,
  максимум 180 тел, уникальные положительные целые ID, допустимые kind и конечные
  числовые координаты/скорости/массы/радиусы.
- Базовые пределы импорта: `mass = 1e-24…1e9 M☉`, `r > 0`, проверяемые числовые
  поля по модулю ≤`1e12`; время `0…1e12` лет, rate `1e-6…100`, scale `1e-5…1e10`.
  Точный перечень границ и дополнительных полей — в `restore` / `SolidPhysics.valid`.
- Имена обрезаются до 36 символов, цвета проверяются как `#RRGGBB`, planet — по
  allowlist. Cuts фильтруются/ограничиваются; это валидация входа, не обещание
  физической осмысленности произвольного JSON.
- `nextId` пересчитывается по максимальному загруженному ID; выбранное/следуемое
  тело восстанавливается только если такой ID существует.
- После восстановления мир **всегда на паузе**, ускорения пересчитаны,
  следы/прогноз/контактные пары/отчёт/эффекты/inspection очищены.
- Радиус ЧД пересчитывается из массы. Вырезы и ориентация сохраняются, сетка
  **не хранится**: Worker реконструирует её заново.
- Поле `scenario` остаётся `solar`, заголовок становится «Своя вселенная»;
  сохранение не создаёт новый стартовый сценарий.
- Это не полный скриншот UI: lightingMode, rotationMode, spin pause, sizeScale,
  все переключатели отображения, состояние лаборатории удара и вкладок целиком
  не сериализуются. `paused` экспортируется, но restore сознательно включает паузу.
- RNG seed и рендер-фазы всех эффектов не сериализуются: JSON не гарантирует
  побитовый replay, хотя хранит физическое состояние и повреждённую форму.

Не менять version/семантику полей без продуманной миграции. Не возвращать старую
сетку по ID без проверки ссылки на solid/epoch после импорта.

## 13. API для диагностики и тестов

API предназначен для DevTools/автотестов, не является стабильным внешним SDK.
Не рассчитывать на доступ к закрытым переменным IIFE напрямую.

```js
const api = window.OrbitFoundry;
api.pause();
console.log(api.getView(), api.time, api.stats);
console.table(api.bodies.map(b => ({ id: b.id, name: b.name, mass: b.mass, r: b.r })));
const earth = api.bodies.find(b => b.planet === 'earth');
if (earth) { api.select(earth.id); api.focusShowcase(true); }
const snapshot = JSON.parse(JSON.stringify(api.payload())); // глубокий снимок!
// api.restore(snapshot); // заменяет текущий мир и включает паузу
```

Важно: `payload()` собирает объект, но некоторые вложенные поля (`solid`, scars,
quaternion) могут ссылаться на текущие данные. Для независимого снимка делать
JSON round trip или `structuredClone`, а не держать поверхностную ссылку.

Основные доступные точки:

| API | Что даёт |
| --- | --- |
| `getView()` | Копия cam + scale/yaw/tilt/W/H. |
| `bodies`, `settings` | Живые ссылки на данные; прямые правки обходят валидацию/UI и могут повредить мир. |
| `time`, `paused`, `selected`, `following`, `cameraFlying`, `surfaceInspection` | Текущее состояние. |
| `select(id)`, `focusShowcase(immediate)`, `fit()`, `zoomBy(factor)` | Выбор и камера. `focusShowcase` — alias `focusPlanet`. |
| `loadScene('solar')`, `payload()`, `restore(data)`, `pause()` | Сцена, снимок, восстановление. `pause` не toggle. |
| `simulate(years)` | Синхронный CPU-шаг с бюджетом; возвращает фактически выполненное время. Не ожидает сетку. |
| `accel(arr)`, `safeStep(arr)`, `leap(dt, arr)` | Низкоуровневые методы; leap сам не разрешает контакты и не двигает глобальное t. |
| `contacts(dt)`, `contactPairs`, `lastImpact`, `launchImpact()`, `inspectImpact()` | Контакты, итог и лаборатория. |
| `project`, `unproject`, `launchVelocity`, `initialLaunchVelocity`, `candidate`, `previewLaunch`, `spawn` | Проекция и инструменты. |
| `launchPath`, `pointer`, `cancelPointer()` | Диагностика жеста запуска. |
| `stats`, `energy`, `G` | Статистика/константа. Геттер stats пересчитывает статистику. |

Дополнительно:

```js
window.ImpactPhysics;              // analyze, swept, fragments, units
window.SolidPhysics;               // field, local/world, cut, overlap, crater, shave, valid, candidates
window.FoundryRenderer.meshStats;
window.FoundryRenderer.pendingSolids();
window.FoundryRendererInfo;        // three, renderer, objects: Map, planetData, camera, sunLight
window.FoundryRendererInfo.objects.get(earth?.id)?.meshAudit;
```

Для нового тестового мира взять deep-clone `payload`, заменить `bodies`, выставить
валидные `settings/camera/t/rate`, сбросить `selected/follow` или указать реальные
ID, затем `restore`. Для ожидания полной геометрии после изменения сначала дождаться
кадра/постановки задания и соответствующего revision/meshAudit, затем пустых очередей:
одна проверка `pendingSolids() === 0` сразу после CPU-контакта может быть преждевременной.

### Минимальный browser smoke

Playwright нужен **только для тестирования**, не для сайта. Использовать уже
установленный пакет или установить локально без коммита node_modules/lock-файлов:

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
# В отдельном терминале: python3 -m http.server 8000
```

Пример из корня проекта (можно сохранить отдельно как smoke-скрипт).
`BASE_URL` и `CHROMIUM_PATH` необязательны. В старой Linux-среде Chromium находился
в `/usr/local/bin/chromium`; в новой среде не считать этот путь обязательным.

```sh
node <<'JS'
const { chromium } = require('playwright');
const assert = require('node:assert/strict');
(async () => {
  const browser = await chromium.launch({
    headless: true,
    ...(process.env.CHROMIUM_PATH ? {executablePath:process.env.CHROMIUM_PATH} : {}),
    args: ['--no-sandbox','--enable-unsafe-swiftshader','--use-gl=angle','--use-angle=swiftshader']
  });
  try {
    const page = await browser.newPage({viewport:{width:1600,height:1000}});
    const errors = [];
    page.on('pageerror', e => errors.push(e.message));
    await page.goto(process.env.BASE_URL || 'http://127.0.0.1:8000/');
    await page.waitForFunction(() => window.FoundryRendererInfo && !document.getElementById('loading'));
    const earthId = await page.evaluate(() => {
      const api = OrbitFoundry, earth = api.bodies.find(b => b.planet === 'earth');
      api.pause(); api.select(earth.id); api.focusShowcase(true); return earth.id;
    });
    const before = await page.evaluate(() => OrbitFoundry.getView().cam);
    await page.keyboard.down('d');
    await page.waitForFunction(before => {
      const c = OrbitFoundry.getView().cam;
      return Math.hypot(c.x-before.x,c.y-before.y,c.z-before.z) > 1e-12;
    }, before);
    await page.keyboard.up('d');
    assert.equal(await page.evaluate(() => OrbitFoundry.following), null);
    await page.keyboard.press('r');
    await page.waitForFunction(id => !OrbitFoundry.cameraFlying && OrbitFoundry.following === id, earthId);
    await page.keyboard.press('t');
    assert.equal(await page.evaluate(() => OrbitFoundry.getView().tilt), 0);
    assert.deepEqual(errors, []);
    console.log('browser smoke: OK');
  } finally { await browser.close(); }
})().catch(error => { console.error(error); process.exitCode = 1; });
JS
```

### Ручная/расширенная матрица

1. **Запуск:** все JS/текстуры/Worker доступны без 404, загрузочный экран исчезает,
   Земля видна, консоль без исключений. Проверить локально и после публикации.
2. **Камера:** W/S/A/D/Q/E по правильным экранным осям; диагональ не быстрее,
   Shift ×4; свободный ПКМ сохраняет позицию глаза, слежение вращает вокруг тела;
   переход T → поворот не переворачивает экран; R возвращает выбранное тело.
3. **Ввод:** поля чисел, select, contenteditable, русская раскладка для новых команд,
   Ctrl/Meta/Alt, help, keyup, потеря фокуса/вкладки и pointer-запуск. Никаких
   «залипших» клавиш или движения после выхода из окна.
4. **Численная часть:** масса/вектор линейного импульса до и после контакта с учётом
   dust, конечные координаты/скорости, корректная отсечка candidates относительно
   brute-force swept на случайных наборах. Отдельно измерять drift на неизменном мире.
5. **Малый кратер:** Земля + пресет астероида `1.26e13 kg`, `1 km`, `20 km/s`;
   проверить реальный вырез, расход ударника, inspection, возврат, экспорт/импорт.
6. **Срезание:** пресет `5.972e24 kg`, `6371 km`, `80 km/s`, `b≈0.72`, автопауза;
   во время контакта состояние движется, после расхождения два остатка сохраняют
   идентичность, выброс учтён, сетки в итоге догружаются. Вариант `b=0` проверяет
   глубокие вырезы/grid, но результат не считать научным прогнозом.
7. **Геометрия:** finite attributes, ориентация/нормали, замкнутость и границы чанков,
   отсутствие дыр/швов, preview → final, повторные локальные cuts и смена метода.
8. **Асинхронность:** во время pending Worker физическое время продолжает идти;
   reset/import/delete при незавершённой задаче не применяют старую сетку к новому ID.
9. **Сохранения:** deep-clone round trip, тело/форма/quaternion, пауза после restore,
   отклонение повреждённого/слишком большого JSON без подмены мира.
10. **Вёрстка:** отдельные снимки и визуальная проверка 1600×1000, 1280×720,
    1100×800 и заглушки 390×844; help, свободный полёт, вид сверху, длинное имя,
    отчёт об ударе, inspection, scroll панелей. Не считать создание PNG проверкой:
    открыть изображения и проверить наложения/обрезание/контраст.

Производительность измерять раздельно: время CPU-физики, время Worker, число
перестроенных patches, GPU-upload, wall-clock до завершения и реальные интервалы
кадров. Встроенный счётчик FPS использует ограниченную dt; при очень длинных
кадрах это не точный независимый профайлер. Не сравнивать только его показания.

   перечитаться. Для Worker учитывать **оба уровня**: URL Worker в `scene.js` и
   `importScripts` внутри `solid-mesh-worker.js`; один `?v` у HTML их не обновляет.
4. Не менять имена импортируемых файлов без проверки относительных путей:
   сайт работает под `/orbit-foundry/`, а не обязательно в корне домена.
5. Дождаться Pages deployment. Проверить HTTP-содержимое опубликованных файлов
   с cache-busting query и сравнить байты/SHA-256 с локальными, а не только статус 200.
6. Открыть живой сайт, дождаться материалов, повторить smoke изменённого поведения,
   проверить консоль/сеть и фактический скриншот. Оставить сайт в понятном состоянии.

Предыдущие крупные JS-обновления загружались через штатную страницу GitHub
`upload/main` и commit в main: инструмент массовой записи упирался в размер payload.
Это особенность прежней среды, не архитектурное требование. В новой сессии
предпочтителен обычный git push/доступный GitHub-инструмент; не предполагать, что
чужая браузерная авторизация или секреты сохранены. README не содержит токенов.

## 16. Типовые неисправности и опасные изменения

| Симптом | Что проверить сначала |
| --- | --- |
| Чёрный экран / вечная загрузка | HTTP, WebGL, ошибки module imports, существование локальных vendor/assets, Worker URL, network/console; не открывать file://. |
| Работает localhost, не Pages | Относительные пути под `/orbit-foundry/`, регистр имён, полный набор зависимостей, кэш и завершение deployment. |
| Видна только мобильная заглушка | CSS-ширина окна ≤1000 px; это намеренное ограничение. |
| «Кратера нет» с общего вида | Реальный масштаб: километровый вырез на планете мал. Проверить lastImpact/cuts и inspection, а не раздувать кратер. |
| Визуальная форма отстаёт | pendingSolids, meshStats, preview/final и meshAudit; физика не обязана ждать сетку. |
| Подвисание при ударе | Не вернулась ли синхронная реконструкция/ожидание Worker; число cuts/triangles, полный reset вместо локального patch, GPU allocations, CPU safeStep. |
| После импорта форма от другого тела | Проверки token/ref/object/epoch, повторно используемые ID, запрос до reset. |
| Кратер вращается относительно контакта | solidLock, solidQuaternion, local/world и prepareSolid; не смешивать spin и вращение ядра. |
| Непонятный ракурс / камера «телепортирует» | Разница cam/eye, selected/follow, origin rebasing, свободный fixed-eye поворот, active flight и точный полюс. |
| Срезанные тела остаются огромными сферами | Повреждённое поле/задание/материал или не тот рендер-объект; физический b.r намеренно не уменьшается вместе с массой. |
| Масса/импульс «исчезли» | Включить dust в сумму; проверить резервирование мест под выброс, поглощение и удаление ядер. Не суммировать только два ядра. |
| ΔE сбросилась к нулю | baselineDirty/energy0. Это не доказательство энергетически точного разрушения. |
| Старый тест падает на loadScene | Удалённые сцены/абсолютные пути исторического теста, а не автоматически поломка текущего приложения. |

**Нельзя незаметно возвращать:** ожидание сетки в simulate; крупные случайные
шары вместо обычного срезания; декоративное пятно вместо вырезанного кратера;
общий упругий отскок всех ядер в fragment; глобальный remesh на каждую revision;
неограниченную очередь Worker; показ незавершённой первичной поверхности;
исчезновение массы выброса; двойной знак ретроградности; использование screenRadius
как физического радиуса; формулу глаза вместо look-at при изменении `cam`.

При добавлении нового поля тела проверить **все** места: создание `body`, clone
в прогнозе, resolver, `payload`, валидацию/`restore`, рендер-кэш и reset.
При изменении формы — согласованность `SolidPhysics`, Worker, quaternion, revision,
планировщика и shader attribute `interior`. При изменении камеры — engine basis,
scene.sync, project/unproject, pick, HUD, zoom и мышь/клавиатуру вместе.

## 17. Ограничения модели и ресурсы

- Максимум **180 агрегированных физических тел**, **256 вырезов на тело**.
  Эти числа не означают, что предельная сцена будет интерактивной на любом железе.
- Контактное удаление — reduced-order кинематический proxy. Нет SPH, FEM,
  уравнений состояния, ударных волн, течения расплава, вязкости, упругой деформации,
  повторной аккреции облаков и полноценной газодинамики гигантов.
- После среза не пересчитываются физический центр масс формы, тензор инерции,
  вращательный импульс и распределение плотности по новым компонентам.
  Вырез может создавать разобщённые геометрические части в одном физическом теле.
- Линейный импульс/масса учитываются в остатках и облаках в пределах численной
  модели; механическая энергия контакта не сохраняется — часть трактуется как
  разрушение/нагрев. Нет обещания точного общего энергетического баланса.
- Медленные/лобовые планетные столкновения, экстремальные плотности/массы,
  предельные cuts и тонкие остатки могут выглядеть неестественно. Это известная
  область ограничений, не результат научного расчёта столкновений планет.
- Пробный контакт, решётка массы и сетка изображения имеют конечное разрешение.
  Грани/стенки глубоких срезов могут быть фасеточными; мелкие детали — теряться.
- Декоративные атмосфера, свечение, линзирование, кольца и свет не калиброваны
  фотометрически. Карты и фазы не дают наблюдательную картину на дату.
